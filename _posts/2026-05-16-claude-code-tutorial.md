## 01｜基本操作

### 启动与交互

```bash
cd your-project-directory
claude
```

启动后，在底部输入框直接打字对话。

### 三个核心工作模式（Shift+Tab 切换）

| 模式 | 行为 | 适用场景 |
|:---|:---|:---|
| **Normal** | 每一步操作都需要你确认后才执行 | **新手首选**，心里有底 |
| **Auto-accept** | Claude 自动执行所有操作，无需确认 | 信任度高的场景，提速 |
| **Plan** | 只看不改，先分析和规划，不写代码 | **先规划，再动手**，避免返工 |

> 💡 **新手建议**：先用 Normal 模式，熟悉后再用 Auto-accept。

## 02｜用 Plan 模式规划

### 标准提示词模板

```
请帮我开发一个番茄钟 Web 应用，技术栈用 React + TypeScript + Tailwind CSS。
功能包括：25 分钟倒计时、开始/暂停/重置、番茄计数、休息提醒。
请先帮我规划一下项目结构和开发步骤，不要写代码。
```

### 关键点

- **明确技术栈**：不让 Claude 自己猜
- **明确功能**：列出具体需求
- **明确要求**：**"先规划不写代码"**

### 规划后的选项

Claude 给出计划后，会让你选择：

1. **自动接受所有修改**（直接改代码）
2. **手动审核每一处修改**（逐个确认）
3. **给 Claude 反馈**，调整方案

> 计划会写入 `.md` 文档，执行时不会乱。

### 遇到问题怎么办？

直接把**问题现象**告诉 Claude Code，让它排查修复。

## 03｜需求不明确？让 Claude 采访你

### 提示词模板

```
我想做一个番茄钟应用，但我还没想清楚具体要怎么做。
请你先不要写代码，而是向我提几个问题，
帮我理清需求，等我们讨论清楚了你再动手。
```

### Claude 会问你什么？

- 技术栈偏好（React/Vue/原生）
- 目标平台（Web/桌面/移动）
- 核心功能细节（倒计时时长、番茄计数、休息提醒方式）
- 数据存储（是否需要历史记录）
- 界面风格

> 这比你自己硬憋需求文档高效得多。

## 04｜页面不好看？用 Skill 美化

### Skill 是什么？

Claude 的**"专业技能包"**，由专业人员编写。安装后让 Claude 在特定领域表现更好。

### 安装 frontend-design Skill

```bash
/plugin install frontend-design
```

安装成功后在 `/plugin` 的 "Installed" 里确认状态为 `enabled`。

### 使用示例

```
番茄钟的功能都完成了，但页面很丑。请用 frontend-design skill 帮我重新设计界面。
我想要简洁现代的风格，暖色调，圆形倒计时显示，配合番茄的红色主题。
```

### 效果

Claude 会输出配色协调、有微交互动画的专业界面。

## 05｜用 @ 精准指定文件

### 用法示例

```
请把倒计时数字改大一点，加一个呼吸动画效果。
@src/components/TimerDisplay.tsx
```

### 多种 @ 方式

| 用法 | 效果 |
|:---|:---|
| `@./src/components/Timer.tsx` | 引用**单个文件** |
| `@./src/components/` | 引用**整个目录** |
| `@file1 @file2` | 引用**多个文件** |

### 核心优势

1. **精准控制**：Claude 只改你指定的文件
2. **节省上下文**：不用满项目乱翻，极大节省 token

> 💡 **习惯**：能 `@` 指定文件就 `@` 指定，别让 Claude 自己去找。

## 06｜复杂功能？用 ultrathink

### 问题

默认情况下 Claude 思考较浅，复杂功能容易漏细节。

### 提示词示例

```
请帮我添加一个番茄统计面板，展示今日完成番茄数、累计专注时长、连续完成天数。
需要考虑数据的持久化存储（localStorage）。请 ultrathink 后给我方案。
```

### 注意事项

- 新版只有 **`ultrathink`** 生效（`think`、`think hard` 已失效）
- 会消耗更多 token，响应更慢，**只在复杂问题时使用**
- 如果想全局深度思考：用 `/effort` 命令调整

## 07｜项目记忆：CLAUDE.md

### 痛点

每次 `/clear` 或重启，都要重新告诉 Claude 项目信息。

### 解决方案

在项目根目录创建 `CLAUDE.md`，Claude 每次启动自动读取。

### 快速创建

```bash
/init
```

### 最佳实践示例

```markdown
# 项目简介
一个帮助用户专注工作的番茄钟应用

## 技术栈
- React 18 + TypeScript + Tailwind CSS

## 代码规范
- 使用函数式组件，不用 class 组件
- 变量命名用驼峰命名法
- 组件文件名用 PascalCase

## 项目结构
- src/components/ - 放 UI 组件
- src/hooks/ - 放自定义 Hook
- src/utils/ - 放工具函数
```

### 核心原则

**"如果删掉这条信息，会不会让 Claude 犯错？"**
- 不会 → 不写
- 会 → 写进去

❌ **不要放**：详细 API 文档、临时需求、泛泛描述

> 💡 CLAUDE.md 是活文档，随项目进展定期更新。

## 08｜改错了？用 Rewind 回滚

### 三种撤销方式

| 方式 | 文件回滚 | 对话回滚 | 适用场景 |
|:---|:---:|:---:|:---|
| **`/rewind` 或连按两次 `Esc`** | ✅ | ✅ | Claude 走错方向，想彻底回到某个节点 |
| **"撤销刚才的修改"** | ✅ | ❌ | 只是代码改错了，对话不用回滚 |
| **`git checkout .`** | ✅ | ❌ | **最靠谱的全局回滚**，不依赖 Claude Code |

### Rewind 操作步骤

1. 连按两次 `Esc` 或输入 `/rewind`
2. 选择要回滚到的历史节点
3. 确认回滚

### 注意事项

Rewind 只能回滚 Claude 直接创建/编辑的文件，无法撤销 `npm install` 等命令生成的 `node_modules`。

### 最佳实践

**在让 Claude 做大改动之前，先手动 `git commit` 一次**

```bash
git add .
git commit -m "功能开发完成，准备让 Claude 重构"
```

万一改坏：
```bash
git checkout .
# 或
git reset --hard HEAD~1
```

> 建议：Claude 一旦跑偏，立刻 `Esc+Esc` 回滚，别等。

## 09｜Claude 变笨了？先压缩再清空

### 原因

上下文窗口快满了（约 200k token 上限）。不是 Claude 变笨，是"短期记忆"不够用了。

### 查看占用

```bash
/context
```

**阈值**：占用超过 **70%**，Claude 开始顾此失彼。

### 两种清理方式

| 命令 | 效果 | 适用场景 |
|:---|:---|:---|
| **`/compact`** | 压缩对话为摘要，保留关键信息 | 继续做**同一个项目/功能** |
| **`/clear`** | **彻底清空**所有对话历史 | 切换到**完全不相关的任务** |

### 使用建议

1. 养成看 `/context` 的习惯
2. 占用超过 70% → 先 `/compact`
3. 只有任务完全不相关时才用 `/clear`

## 10｜关掉终端也不怕：resume 恢复

### 问题

退出 Claude Code 再打开，是新会话，之前的对话历史不在了。

### 解决方案

```bash
# 从列表中选择一个历史会话恢复
claude --resume

# 直接恢复最近一次会话（最快）
claude --continue
# 或
claude -c
```

### 效果

聊了什么、改了什么文件、上下文是什么，全部都在。

> 放心关终端，Claude Code 会自动保存会话。

## 11｜代码质量把关：子代理 Code Review

### 痛点

让 Claude 审查自己写的代码，会"手下留情"，问题看不出来。

### 解决方案

创建独立的 Code Review 子代理。

### 创建步骤（`/agents` 命令）

1. 输入 `/agents`，选择创建子代理
2. 选择作用域：`Project`
3. 选择"让 Claude 自动生成"
4. 描述职责（示例）：

```
你是一个代码质量审核员，专门负责审查 React + TypeScript 项目。
检查点：定时器清理、事件监听器移除、空值处理、可访问性、性能隐患。
输出格式：按"严重"、"中等"、"建议"三级分类报告。
```

5. 配置权限、选择模型、选择颜色（如绿色）
6. 完成创建

### 使用子代理

```
用 code-quality-reviewer agents 帮我审核这个项目的代码
```

### 子代理 vs Skill

| 对比维度 | **Skill** | **子代理** |
|:---|:---|:---|
| **谁干活** | 主对话的 Claude 自己 | 后台新建独立的 Claude 实例 |
| **上下文** | 占用**主会话**上下文 | 拥有**独立的**上下文窗口 |
| **来源** | 从插件市场安装 | 通过 `/agents` 自定义创建 |
| **适用场景** | 让 Claude 在某个领域做得更好 | 用**独立视角**完成任务 |

## 核心理念

> Claude Code 不是一个自动写代码的"万能工具"，而是一个**能力很强但需要你正确引导的搭档**。你给的信息越清晰，产出质量越高；工作流越规范，效率越高。
